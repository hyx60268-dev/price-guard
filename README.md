# 价格守卫

价格守卫在 GitHub 云端运行，为多账号店铺提供三平台比价、商家选品和采购报价。电脑与手机无需保持开机。

[打开仪表盘](https://hyx60268-dev.github.io/price-guard/) · [六项核心需求](docs/product-requirements.md) · [商家追踪](docs/merchant-monitor.md)

## 产品目标

比价准且快、选品有用、图片能用、文案能直接用、成本自动找准、软件省心。以[核心需求](docs/product-requirements.md)为当前交付标准；日期命名的诊断文档记录历史，不覆盖后续用户要求。

当前已有三平台并发检查、全账号排除逻辑、跨设备加密同步、站外找图与多渠道采购查询。功能存在不等于全部验收完成：自动采购报价、全量图片、部分自家库存漏排及全库存刷新时效仍需真实数据验证。

## 日常使用

1. 打开并解锁仪表盘，在账号管理或商家追踪中维护主页。
2. 查看比价、选品及各项真实更新时间；按需填写采购价、人肉费和日本物流费。
3. 修改后按对应按钮同步云端；当前通过加密 GitHub Issue 交接，用户提交有正文的 Issue 后由后台合并。
4. 选品中的“已上品”立即在本机隐藏，完成同步后在其他设备保留。
5. 日文标题、日文详情和中文对照分别复制。

同步内容先在本机加密。剪贴板失败时可从可见文本手动复制；长内容不会以空正文 Issue 冒充成功。已保存的主页无需反复录入。

## 价格与成本

- 比价使用外部、当前在售且规格可比的商品；系统内全部自有卖家及商品都应排除。
- 普通挂牌价与优惠券、入会奖励分开，不能把个人优惠当人人可用报价。
- 自动采购报价必须保留实际详情、目标规格、卖家、价格与核验时间。当前实现仍保留独立卖家交叉核验；替代方案需先验证后替换。
- 人工实际采购价优先。未知成本和费用保持未知，不自动编造金额。
- 来源受限时其他独立来源继续工作。真实登录或验证按平台要求处理。

现有成本公式保持：

    成本日元 = 向上取整（（（采购价人民币 + 人肉费人民币）× 人民币兑日元汇率 + 日本物流费日元）× 1.05）

页面分别展示当前售价与建议售价对应的利润。

## 数据与运行

账号、人工费用、纠错、已上品及必要历史通过加密状态保存。员工只访问自己获授权的数据；全系统自有商品排除不能泄露其他账号的私有信息。

定时任务、商品核验和页面发布分别记录状态。每轮运行只代表该轮实际覆盖，不能把定时触发间隔当成全库存刷新保证。失败不能覆盖可靠的新数据，也不能让旧报价获得新的核验时间。

通知沿用 GitHub Issues 和用户通知偏好。已授权的维护主动推进；普通扫描、成本采集及找图在 GitHub 云端执行。

## 开发与部署

仓库根目录是唯一运行版本；`price_guard_work/` 为历史副本。维护前阅读 [AGENTS.md](AGENTS.md)。

本地运行代码测试：

    npm ci
    npm test

真实业务扫描及发布由 `.github/workflows/` 中的 GitHub Actions 执行。部署之后还需核对线上代码版本、数据时间和目标商品，不能只看绿色部署标记。

仪表盘使用 `DASHBOARD_PASSWORD`，用户配置可通过 `PORTAL_USERS_JSON` 兼容输入。闲鱼正常授权会话沿用 `XIANYU_AUTH_PART_1`、`XIANYU_AUTH_PART_2`、`XIANYU_AUTH_PART_3`，并兼容旧的加密存储状态配置。私密内容不得进入公开日志或仓库文件。
