# 价格守卫 v7（Yahoo!フリマ × メルカリ × 闲鱼）

价格守卫在 GitHub Actions 云端运行，电脑和手机都可以关机。系统约每 20 分钟先读取所有 Yahoo!フリマ 卖家主页，再检查仍在售同款价格；既会在竞品更低时建议降价，也会在多个可靠竞品一致高于自己时建议提价。只有需要补充采购价时才按需核验闲鱼成本。

仪表盘：<https://hyx60268-dev.github.io/price-guard/>

## 选品发现

仪表盘顶部新增“选品发现”。后台用以下固定标准寻找候选：

1. 在メルカリ和Yahoo!フリマ搜索“中国限定”；
2. 每轮目标至少检查 200 条、每个平台最多读取最新的 200 条已经卖完且成交价不低于 ¥4,999 的搜索结果；
3. 进入出品者主页，按新到旧读取近30天成交记录；
4. 同一商家近30天内的同款独立成交记录达到2件才认定为热卖，不把专用链接、まとめ商品、不同角色、不同数量或残次品合并；
5. 将日文标题整理成闲鱼中文搜索词，打开闲鱼候选详情核对标题、正文、规格、价格与多图；
6. 至少两个可信价格样本，并能从同一可信闲鱼商品取得至少2张与日本卖家原图不重复、背景和画幅连贯的实拍图时，才标记“已核验”；
7. 自动生成不超过40字的日文标题和重新整理的日文商品简介，可在手机或电脑一键复制。

选品深度扫描约每6小时刷新一次，其余每20分钟价格检查直接复用缓存。扫描会自动排除 `config/accounts.json` 以及网页同步的所有自有 Yahoo!フリマ 账号和商品。新增已核验热卖品时沿用 GitHub App、邮件或 Telegram 手机提醒。第三方原图不会提交进 Git 仓库；发布 Pages 时仅生成适合手机分享的压缩缓存图，方便交给闲鱼/小红书 App 搜图。

## v7 解决的问题

- **同首图不再漏判**：Yahoo 商品页“相似商品”成为每轮主要召回源；标题写法不一致时，可由同商品族、足够明确的角色/型号词和强首图相似度共同确认，但数量、版本、单品/套装明确冲突仍会硬性排除。
- **双向调价**：低价竞品触发降价；至少 2 个独立卖家、价格区间一致且都高于自己时也会触发提价。默认自己的售价不高于可信市场中位价的 82%，且至少少卖 ¥1,500，才建议提价，避免被单个虚高挂牌带偏。
- **多人自助管理**：管理员可在网页创建用户名、密码和昵称；员工首次同步后绑定其 GitHub 身份，并可自行维护自己的店铺和通知邮箱。
- **手机搜图交接**：闲鱼与小红书各有独立按钮，先把同源缓存图交给系统分享/保存面板，再尝试打开对应官方入口。
- **公平排队与轻量扫描**：多个店铺按轮转顺序检查；商品页相似推荐每轮更新，昂贵的全站文字搜索默认每 6 小时轮换一次。加密 GitHub Issue 是持久输入队列，每次任务都会按创建顺序合并全部待处理请求，因此多人连续提交也不会丢中间一份。

- **成本跨设备同步**：采购价、人肉费、日本物流费先保存在本机，再用仪表盘密码端到端加密，通过 GitHub Issue 交给后台合并；公开仓库只出现密文。
- **页面自动更新**：页面每分钟及重新回到前台时检查新版本；数据有变化会自动解密重载。新版 Service Worker 会立即接管，安装到手机桌面的页面不再长期停在旧版本。
- **双利润**：网页详情、电脑表格、手机卡片和 Excel 同时显示“不改价利润”和“改价后利润”。
- **重新上架继承成本**：成本除 Yahoo 商品 ID 外还绑定稳定的商品身份。标题/闲鱼搜索词明确相同时，重新上架换 ID 仍会继承；若存在多个完全同名商品则不自动迁移，避免串错成本。
- **多账号真正进云端**：网页“账号管理”新增的 Yahoo 主页在同步后加入后台扫描，不再只是当前电脑的快捷入口。
- **增量与受控并发**：先发现各账号新增、减少和重新上架，再以最多 3 路账号主页并发、Yahoo 商品任务公平轮转处理；15 分钟内的刚生成结果复用缓存，单轮有 18 分钟扫描预算，超时项目显示缓存/延后而不会拖死后续定时任务。
- **闲鱼按需缓存**：有人工采购价时不查闲鱼；可靠闲鱼样本 7 天内复用；每轮最多深度核验 3 件待补成本商品。
- **低价钩子保护 v2**：先用文字召回候选，再打开详情，同时核对标题、正文、选款/规格和多张图片。至少 2 个详情与价格区间一致的样本才计算均价。

## 成本与利润

每件商品由用户填写三个值：

1. 采购价（人民币；若自动闲鱼均价可靠，可留空使用均价）；
2. 人肉费（人民币）；
3. 日本物流费（日元）。

公式：

    成本 = ((采购价人民币 + 人肉费人民币) × 人民币兑日元汇率 + 日本物流费日元) × 1.05

最终向上取整。系统不再按商品大小猜人肉费或日本物流费。

## 手机和电脑同步

1. 在任意设备打开并解锁仪表盘；
2. 录入成本，或在“账号管理”添加 Yahoo 卖家主页；
3. 点“同步云端”；
4. 在打开的 GitHub 页面点一次绿色 **Submit new issue**；
5. 后台完成后会关闭该 Issue，已打开的仪表盘会自动刷新。

## 多人分店管理

总管理员用户名固定为 `admin`，密码就是现有的 `DASHBOARD_PASSWORD`；程序不会读取或公开这个密码。管理员在网页“账号管理”里填写昵称、用户名和初始密码即可创建员工，无需再手写 `PORTAL_USERS_JSON`。新员工可以先获得一个空账号，登录后自行添加自己的 Yahoo 店铺和通知邮箱。

员工第一次成功提交同步 Issue 时，后台会把该员工账号绑定到实际提交者的 GitHub 用户名；后续其他 GitHub 账号无法冒用该网页账号同步。员工只能查看、下载和修改自己名下的数据，也不能认领已经属于其他员工的店铺。管理员可重置密码、停用账号或解除 GitHub 绑定。

每位用户登录后可在“账号管理”填写自己的通知邮箱并加密同步。扫描发现变化时，系统会先按 `accountIds` 过滤：员工只收到名下店铺，管理员收到全部店铺。邮件地址无法自动换取邮件服务商密钥——API 密钥属于发信方权限，不能从收件邮箱推导。网页内已提供简明教程；管理员只需在 Resend 验证发件域名、创建 API Key，再到仓库 Actions Secrets 设置：

- `RESEND_API_KEY`：Resend 邮件 API 密钥；
- `NOTIFY_FROM_EMAIL`：已在 Resend 验证域名下的发件地址，例如 `价格守卫 <notify@example.com>`。

邮箱地址保存在加密状态里，不会写入公开的 `users.json`。如果暂未配置上述两个 Secret，原有 GitHub Issue / Telegram 降级提醒仍会继续工作。

由于这是公开仓库的静态 GitHub Pages，网页里不能安全存放 GitHub 写入令牌；因此最后的 GitHub 提交必须由已登录的仓库所有者确认一次。同步内容使用与仪表盘相同的 AES-256-GCM 加密，Issue 中不含明文成本。

## 多账号

网页右上“账号管理”可添加多个：

    https://paypayfleamarket.yahoo.co.jp/user/...

保存后点“同步成本和账号到云端”。同步工作流会先显示“待首次扫描”，下一次定时扫描会自动发现该账号当前在售商品。每个账号的库存、Yahoo 比价、成本与重新上架映射互相隔离。

仓库内的 `config/accounts.json` 仍可保留固定账号；网页同步的账号保存在加密状态中。无需为网页新增账号手工创建 catalog。

## 闲鱼图片核验的边界

GitHub Actions 运行在 Linux 云端，只能使用闲鱼桌面网页，不能远程控制 iPhone/Android 上的闲鱼 App，也不能安全依赖其私有“以图搜索”接口。桌面网页当前没有图片上传搜索入口，因此自动流程采用：

1. 商品词召回候选；
2. Yahoo 主图/详情图与闲鱼卡片图、详情多图做感知相似度比较；
3. 同时检查闲鱼详情标题、正文、规格、数量、角色、版本、箱损/残次描述；
4. 排除选款、拍后改价、补差价、系列最低价等钩子。

Yahoo 最低价同样执行严格核验：候选必须当前在售，并同时通过实物类型、角色/版本、数量、包装与成色、详情文字和实物图片验证。立牌与票卡/贴纸、新品未拆与开封展示/无盒、完整商品与仅外盒均会被硬性判为不可比。

商品详情和选品发现卡片分别提供“闲鱼搜图”和“小红书搜图”。点击后会显示准确的来源首图，并优先把 Pages 构建时生成的同源压缩图作为真实图片文件交给手机系统分享/保存面板；保存完成后页面会尝试打开对应官方入口，若手机阻止自动跳转，也可点同一窗口里的打开按钮。手机系统不允许网页静默写入相册，也不允许网页代替用户点击目标 App 内的相机按钮，因此最后一步仍需用户在闲鱼或小红书 App 内选择刚保存的图片。自动结果仍以详情和多图共同验证为准，不会把仅在正文顺带出现名称的 ¥3 系列商品当成目标成本。

## 调度与缓存

- GitHub 定时触发频率：约 20 分钟；GitHub 自身可能有几分钟排队延迟。
- 工作流最长 90 分钟；日常价格扫描仍按独立预算停止启动新 Yahoo 请求。选品发现每6小时深度刷新一次，其他轮次直接复用加密缓存。
- 扫描、代码推送、手工运行和多人同步共用串行发布队列；即使等待中的 Actions 任务被新触发替换，尚未处理的加密 Issue 仍会由下一次任务按顺序合并，不会同时覆盖状态。
- 所有账号主页优先刷新，因此即使比价预算不足，也能识别各账号的新增、减少与重新上架。
- 闲鱼可靠缓存有效期默认 7 天；Yahoo 刚完成的 15 分钟内结果可复用，避免部署/同步紧接着重复抓取。

## 手机通知

数据有变化时，默认创建 GitHub Issue，显示“建议降价/建议提价”、变动商品摘要和仪表盘链接，但不公开成本或利润。可安装 GitHub 手机 App 并允许通知，也可直接查看：

<https://github.com/hyx60268-dev/price-guard/issues>

如果仓库设置了 `TELEGRAM_BOT_TOKEN` 和 `TELEGRAM_CHAT_ID`，变化提醒优先发送 Telegram 私聊。

## GitHub Secrets

必需：

- `DASHBOARD_PASSWORD`：至少 8 位；
- `XIANYU_AUTH_PART_1`
- `XIANYU_AUTH_PART_2`
- `XIANYU_AUTH_PART_3`

兼容旧的 `XIANYU_STORAGE_STATE_GZIP_B64` / `XIANYU_STORAGE_STATE_B64`。Yahoo 使用公开页面，不需要 Yahoo 登录信息。

即使闲鱼登录失效或云端网络被限制，Yahoo 库存与价格检查仍继续；未能同时核对正文和图片的闲鱼候选不会自动计入成本。
