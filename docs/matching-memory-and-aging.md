# 共享同款核验、纠错记忆和30天提醒

2026-09-23，本次仍只使用现有云端运行方式，不需要用户设备常驻。

## 同款标准

Yahoo 比价和闲鱼成本先经过同一套硬性核验：双方详情必须可读，简介中的实际出售内容优先于系列名称；数量、端盒/单盒、颜色、品相或版本冲突均排除。卡牌、立牌和颈枕须通过首图证据检查。通过这些条件还需要各平台后续同款核验；闲鱼仍需详情实价和至少两个独立卖家。

闲鱼原来主要使用搜索词与候选标题的销售单位判断，本次补上自己的商品简介和候选全文；选品成本也传入来源商品简介。选品跨平台分组共用销售内容约束，不能把两本和三本的成交合计到同款。

哈希图片相似度不是具有人工理解能力的视觉模型；真实同款重拍可能被拒绝。上述改动旨在降低误匹配，不承诺已测得真实市场准确率提高，也不代表闲鱼登录/安全验证已经恢复。旧自动参考按新规则重新核验，人工费用保留。

## 纠错如何保留

商品详情新增“同款纠错记录”，可将当前 Yahoo 或闲鱼样本标记为“不是同款”，也可以撤销。保存后本机旧建议立即停用；通过既有加密同步入口提交后，云端长期保存并在后续匹配时排除。云端同步仍需完成现有 GitHub 提交流程，不能把仅保存在本机当作已同步。

排除记录按店铺、商品和候选隔离；重新上架时只在关联 ID、标题和主图一致时沿用。普通用户不能修改其他人的店铺。撤销记录保留时间戳，旧扫描缓存不能复活已撤销的规则。

广义修复进入共享规则，并将用户真实错误保存为 `test/fixtures/user-match-regressions.json` 和现有回归测试。以后每次修改须运行旧例、补充新例，测试不通过不能发布。`AGENTS.md` 保存了这一维护要求。这是可审核的规则和纠错记忆，不是模型自动训练；单条排除不会擅自推广到所有类似商品。

## 30天未售

页面新增筛选、数量和详情提示，Excel 同步显示天数与时间依据。只有本轮确认仍为 OPEN 的同一条商品，达到30天才建议评估删除。

优先用商品详情 `openDate`，并绑定其商品 ID；拿不到时从首次确认在售计时。更新日期不能代替上架日期，重新上架不能继承旧条目的年龄。主页失败时暂停删除建议。这里只建议，不会删除或下架，也不把本条在售时间说成整个款式30天没有成交。

## 验收范围

受控测试覆盖历史错配、正向同款、日中数量/颜色、三店铺现有回归、纠错账号隔离、旧缓存合并、撤销、真实加密同步脚本及30天边界。测试数量不是已检查的商品数量。是否已发布、真实闲鱼自动参考数量，仍以对应云端运行和发布数据为准。
