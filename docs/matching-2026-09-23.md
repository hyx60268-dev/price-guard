# Offer identity repair — matching rules 14

## Reproduced failures in rules 13

- `saleUnitEquivalent("写真集\n3冊セット", "写真集\n黒とベージュセット売り、別売り不可")` returned true. 冊 and non-numeric sale-member lists were not recognised.
- `hasExplicitDefect` returned false for `初期きずスレあり` and `汚れはシュリンクか本体かは不明`.
- Generic Giyu acrylic-stand titles and Kitty neck-pillow titles did not require visual identity evidence. The actual Melon Giyu title includes 新繹シリーズ; the Momoka title does not. The old check depended on that wording, despite both needing artwork verification. This demonstrates a code-path difference; it is not a reconstruction of the historical encrypted dashboard cache.
- All-image maximum similarity could be provided by a shared secondary package/back photo. Global average colour is not a SKU check.
- Wrong seller categories could override the physical type in a title: Momoka's Fan Ho book `z680530416` is categorised as トレーディングカード.
- Budget-deferred rows merged prior Yahoo fields and market statistics back into new-version baselines, allowing stale diagnostics to survive invalidation.

## Changes

1. Explicit body sale contents are hard constraints; recognise 冊, kanji counts, and colour-member set offers. Uncertain or conflicting sale contents are not equated.
2. Read actual scratches/dirt while retaining generic manufacturing-disclaimer exclusions.
3. Neck pillows have a product family. Acrylic/card/neck-pillow identity needs near-duplicate primary-image evidence, not merely identical generic titles or secondary images. Use all three hashes and spatial RGB differences conservatively. This is not a semantic vision model: different photographs may require review even for genuinely identical goods.
4. Explicit product colour lines in descriptions can reject conflicting variants even if titles/photos agree.
5. Missing own/candidate description blocks automatic acceptance. Unconfirmed lower candidates hold the current price and report incomplete verification.
6. Explicit heading product type outranks an unrelated seller category; plush-keychain category refinement remains supported.
7. Rules-version invalidation applies through the common scan path to all configured shops. Remove prior Yahoo/market-field merges on deferred baselines. Manual costs are not changed.
